# 答案：接口定义的设计

> 对应：[interface-design.md](../design/interface-design.md)

## 第 1 题

**（a）** 不确定（未初始化）。`SKIP` 什么都不做，连消息里写的默认值 0.05 也不填 📐；`fill` 又不写 `resolution`，发出去的是那块内存里原来的值，可能是 0、可能是垃圾，下游按它换算坐标就会出错。这是"未定义行为"，不一定每次都表现出来，所以很难查。💡

**（b）** 用 `DEFAULTS_ONLY`：只填有默认值的字段（`resolution = 0.05`），其他字段（包括 1 MB 的 `cells`）不初始化，交给 `fill` 写满 📐。实测 `DEFAULTS_ONLY` 构造耗时接近 0，resolution=0.05 🔍。这个模式就是为"以后给消息加一个带默认值的字段时，旧代码仍然正确"设计的。更进一步可以复用消息对象，或者用借用消息，连分配都省掉。💡

**（c）** 不会，反而最慢。`ZERO` 要把整个数组清零，而且忽略默认值（resolution 变成 0.0）🔍。实测 1 MB 消息：ALL ≈ 23 µs，ZERO ≈ 47–57 µs，因为 Rolling 生成的构造函数在 ZERO 分支里把数组清零了两次 🔍。

## 第 2 题

**（a）** 例子（💡）：`Footprint` 原来是 `float64 length`、`float64 width`。假如有位置构造函数，代码写成 `Footprint(0.8, 0.5)`（长 0.8、宽 0.5）。后来有人为了和另一个消息对齐，把字段顺序改成 `width`、`length`。这行代码仍然能编译，因为两个参数都是 `float64`，但含义悄悄变成了"宽 0.8、长 0.5"，代价地图里的机器人轮廓转了 90°。编译器不会提醒，只有机器人蹭墙了才发现。同理，在中间插入一个同类型、带默认值的字段也会让后面的参数整体错位。设计文档的原话是：依赖位置参数的代码会在消息定义改动时"以隐蔽的方式"出错，这会让大家不敢演化消息定义 📐。

**（b）**
- **setter 链**（`msg.set__x(1.0).set__y(2.0)`）：新字段没被设置也能编译，新字段取默认值（按构造时的 `MessageInitialization`）。适合"新字段有合理默认值、老代码不用管"的情况，向后兼容好。🔍
- **builder**（`build<Pose2D>().x(1.0).y(2.0).theta(0.5)`）：必须按顺序给出**所有**字段才得到消息；加了字段后旧代码**编译失败**，逼你逐个检查构造点 🔍。适合"每个字段都必须由调用方认真给值"的消息，例如控制指令、安全相关的配置。💡

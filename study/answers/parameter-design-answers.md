# 答案：参数的设计

> 对应：[parameter-design.md](../design/parameter-design.md)

## 第 1 题

**（a）** 先改速度：新值 `max_vel_x=0.3`，旧值 `acc_lim_x=1.5`。校验回调看到的是"速度 0.3、加速度 1.5"，`1.5 > 2 × 0.3 = 0.6`，所以拒绝，速度仍是 1.0 🔍（练习里 `max_speed`/`max_accel` 的同样情形）。如果反过来先改加速度到 0.5，`0.5 <= 2 × 1.0`，这一步能通过，然后再改速度到 0.3，`0.5 <= 0.6` 也能通过。所以逐个改时，结果取决于**顺序**，改错顺序就会卡在中间：要么被拒，要么留下一半旧值。💡

**（b）** 用原子设置，让两个新值一起校验：`ros2 param set /planner max_vel_x 0.3 acc_lim_x 0.5 --atomic`，或者在代码里调 `set_parameters_atomically`。校验回调一次看到两个新值，`0.5 <= 0.6`，一起生效；任何一个不合法就都不生效 📐 🔍。注意 `ros2 param load` 是逐个设置的，不能解决这个问题 🔍。

**（c）**
- 范围 0–1.5 写在**参数描述**的 `floating_point_range` 里。框架会自动检查，`ros2 param describe` 和图形工具也能读到这个约束，这正是设计文档"把约束告诉外部工具"的目标 📐 🔍。
- "加速度不超过两倍速度"涉及两个参数，描述表达不了，只能写在 `add_on_set_parameters_callback` 里，外部工具看不见 🔍。回调只做判断、尽快返回，并在 `reason` 里写清楚拒绝的原因 📐。

## 第 2 题

**（a）** `-p 节点名:参数:=值` 只对**根命名空间**里的节点有效。`planner` 这个前缀匹配不到 `/robot1/planner` 和 `/robot2/planner`，所以静默无效。写成 `-p /robot1/planner:...` 又会解析报错 🔍。原因是 `-p` 的节点前缀按"不带命名空间的节点名"存起来，而参数覆盖按节点全名匹配（和 YAML 里写 `planner:` 匹配不到 `/robot1/planner` 是同一个原因，见卡片坑 3）💡。

**（b）** 下面任选一种：
- YAML 里写 `/**/planner:` 加 `ros__parameters: {use_sim_time: true}`，或者分别写 `/robot1/planner:` 和 `/robot2/planner:`，再用 `--params-file` 传入 🔍。
- 不带节点前缀：`-p use_sim_time:=true`。它相当于写在 `/**` 下，进程里所有节点都会收到 🔍。在 launch 里给每个 `Node` 传 `parameters=[{'use_sim_time': True}]` 效果一样。💡

**（c）** ROS 1 里 `use_sim_time` 是参数服务器上的一个全局参数，谁都能读，写错了名字也只是多出一个没人读的参数，同样不会报错。真正的差别在**所有权** 💡：
- ROS 1 中任何节点都能改别人的参数，节点自己不知道，也没人校验。
- ROS 2 中参数挂在节点上，由节点校验，寿命跟着节点走，名字也没有歧义 📐。

代价是没有真正的"全局参数"。每个节点都要单独拿到配置，所以命令行、YAML 怎么匹配到具体节点就变得很重要，这类匹配错误往往是静默的 🔍。加上"必须先声明"之后，拼错参数名会在设置时被拒绝，这部分问题能提前发现；但节点名写错时什么也不会发生。

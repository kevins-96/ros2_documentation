## 题 1：4 线程也救不了控制环

**结论：** 控制定时器两次触发的最大间隔大约是"一个周期 + 一次激光回调"，即 20 + 40 ≈ 60 ms 量级（推导值，未实测；实际还会受调度抖动影响）。

**推理：**
1. 两个回调都没指定组 → 都在节点默认回调组。📄
2. 默认组是互斥组 → 组内任意两个回调不能并行。📄
3. 所以 4 个线程里同一时刻最多只有 1 个在跑这个节点的回调，等同于单线程。📄
4. 最坏情况：定时器刚在 t = 0 触发完，激光回调在 t ≈ 19.9 ms 开始，占用到 ≈ 59.9 ms；定时器在 t = 20 就绪，却只能等到激光回调结束才执行。

**要点：** 线程数只决定"最多能并行几个"，能不能并行由回调组决定。

## 题 2：拆成两个节点以后

**结论：** 不会再被阻塞（在线程够用的前提下）。

**推理：**
1. 默认回调组是**每个节点各自一个**（文档用的是 "the node's default callback group"）。📄
2. 拆成两个节点后，控制定时器在 `controller` 的默认组，激光回调在 `scan_filter` 的默认组 → 属于不同组。
3. 不同组的回调总是可以并行 📄，4 线程执行器有空闲线程，所以激光回调运行时控制定时器照样能被另一个线程执行。
4. 🔍 [card_executor_min.cpp](../labs/executor_lab/src/card_executor_min.cpp) 就是这个结构，实测 `controller` 与 `planner` 的回调跑在不同线程上，规划期间控制环继续打印。

**延伸思考：** 拆节点是"顺带"得到了不同回调组。在同一个节点里显式建两个互斥组，效果相同，而且不用为了并发改节点划分。见[回调组卡片](../cards/callback-group.md)。

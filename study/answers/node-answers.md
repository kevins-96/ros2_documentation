# 答案：节点与 ROS 图

> 先在[卡片](../cards/communication/node.md)里自己写下答案再来对照。

## 题 1：一个容器进程里的两个节点

- `ros2 node list` 显示 **2 个节点**（另外还可能看到容器节点本身，例如 `component_container`，💡 取决于启动方式）。📄 节点是 ROS 图里的参与者，和进程数无关。
- `ps` 看到 **1 个进程**。📄 一个进程可以包含多个节点。
- `controller_server` 抛出未捕获异常时，**整个进程退出**，`planner_server` 一起没了。💡（C++ 语义推导）这是"放进同一进程"的代价：省了进程间拷贝，但失去了故障隔离。

**要点：** 节点是"逻辑单位"，进程是"故障与资源单位"。决定组合方式时两者要分开考虑。

## 题 2：看得见节点，收不到 /odom

按可能性从高到低（💡 经验排序）：

1. **QoS 不兼容**。`ros2 topic info -v /odom` 在两台机器上分别看发布端、订阅端的 Reliability、Durability。📄 被发现不代表能通信，QoS 是按端点对单独检查的。
2. **话题名或类型不一致**（名字空间不同、拼错、类型不同）。`ros2 topic list -t` 对比两边。📄 FAQ 第 4 条。
3. **数据流量被网络挡住**。发现用的流量通了，但数据流量（不同端口、或多播/单播差异）被防火墙挡住。📄 FAQ 第 6 条。💡 在机器人本机上 `ros2 topic hz /odom` 确认发布正常，再在工作站上看。

域 ID 不同、发现范围限制这两条在本题里可以排除：如果是它们，工作站连 `base_driver` 这个节点都看不到。📄

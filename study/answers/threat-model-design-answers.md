# 答案：威胁模型

> 对应：[threat-model-design.md](../design/threat-model-design.md)

## 第 1 题

**（a）不可信组件** 📐。设计文档的定义：可信组件由应用所有者（或审查过的伙伴）自己开发、构建、测试、部署；第三方节点即使没有恶意，质量保证和发布流程也不受你控制。

**（b）STRIDE 举例**（💡，按设计文档里"第三方跟踪节点"的思路套用）：

| 类别 | 具体后果 |
|---|---|
| T 篡改 / 完整性 | 故意把行人轨迹预测到别处：规划器以为路是空的，径直开过去撞人；或者反过来，到处预测出行人，机器人一直原地不动 |
| D 拒绝服务 | 占满 CPU 或内存，局部规划器的周期被拖长，错过截止期；或者以很高频率发布，挤占带宽 |
| I 信息泄露 | 它订阅了相机和激光，可以把数据传到外部服务器 |
| E 提权 | 和规划器在同一个进程或同一个系统用户下运行时，能读到别的 enclave 的私钥、改配置文件 |
| S 冒充 | 和控制器在同一个 enclave 时，可以直接发 `/cmd_vel`（权限是并集，见[访问控制策略的设计](../design/access-control-design.md)） |

**（c）SROS2 挡不住的** 📐 💡：

- **"合法但错误"的数据。** 它有权限发 `/predicted_paths`，发什么内容 SROS2 不管。设计文档把"节点发出错误数据"列为 13 分的威胁，缓解办法是"校验收到的消息"，而 IDL 层的自动校验还没实现 ⏳。
- **在允许范围内刷屏**：DDS-Security 只管"能不能发"，不管频率 📐。
- **资源耗尽**：要靠操作系统限制 💡。
- **从允许的输出通道泄露数据**：如果它本来就有网络访问权限。

规划器这一侧能做的 💡：

1. 校验物理合理性：预测的行人速度、加速度有上限（比如速度不超过 3 m/s），位置要和自己的激光、代价地图大致一致。
2. 检查时间戳和频率：太旧的预测丢掉；频率异常高时只处理最新一条。
3. 预测只能"加保守"，不能"减保守"：可以因为预测而减速、绕行，但不能因为"预测说没人"而缩小基于激光的安全距离。
4. 保留一层不依赖这个节点的安全层：例如直接基于激光的停车区域。
5. 部署上：单独进程、单独 enclave、单独系统用户，systemd 里加 `CPUQuota=`、`MemoryMax=`。

## 第 2 题

DREAD 是经验打分，下面是一种合理的打法 💡，重点是理由和排序。

**（a）伪造 `/initialpose`（没开 SROS2）：约 14 分**

| 项 | 分 | 理由 |
|---|---|---|
| D 伤害 | 3 | 定位跳到错误位置，机器人按错误的位姿规划，可能撞人、撞货架 |
| R 可复现性 | 3 | 每次都能成功 |
| E 可利用性 | 3 | 一条 `ros2 topic pub` 命令，不需要任何凭据（设计文档："没有 SROS 时任何节点可以发布任何话题"📐） |
| A 受影响用户 | 2 | 机器人周围的人和这一台机器人（车队共用网络时会更多） |
| D 可发现性 | 3 | `ros2 topic list` 就能看到 `/initialpose` |

**（b）拷走 SD 卡里的地图和日志：约 9 分**

| 项 | 分 | 理由 |
|---|---|---|
| D 伤害 | 2 | 泄露场地布局和运行记录，没有直接的人身伤害；如果私钥也在卡上，伤害更大 |
| R 可复现性 | 2 | 每次都要重新接触到机器人 |
| E 可利用性 | 2 | 要物理接触和一点时间 |
| A 受影响用户 | 1 | 主要是部署方 |
| D 可发现性 | 2 | 需要知道 SD 卡在哪、怎么拆 |

**先处理（a）**：分数高，而且远程就能做、门槛极低。缓解：开 SROS2 并 `Enforce`，`/initialpose` 只允许操作员的 enclave 发布 📐；定位节点里对 `/initialpose` 做合理性检查（跳变距离、来源）💡。（b）用加密文件系统（设计文档建议 dm-crypt / LUKS 配合 TPM）📐，私钥不要明文放在卡上 💡。
